# Пакет для GitHub Pages

Эта папка публикует только статический интерфейс. В ней нет личных целей, недельного плана, SQLite, пароля, его хеша, исходных записей, календарных событий, ключей или токенов.

## Подключение API

До настройки сервера страница честно показывает: «Сервер личного плана ещё не подключён». Она не отправляет пароль и не обращается к пути `/api` на домене GitHub Pages.

После появления отдельного HTTPS-сервера внесите только его origin в `config.js`:

```js
window.DASHBOARD_CONFIG = Object.freeze({
  apiBase: 'https://dashboard-api.example.com'
});
```

Сервер должен реализовать существующие пути `/api/session`, `/api/login`, `/api/state` и `/api/logout`, разрешать origin опубликованной страницы через CORS, поддерживать cookies с `SameSite=None; Secure` для работы между доменами и принимать CSRF-токен. Не добавляйте пароль, хеш пароля, cookie или ключи в `config.js`.

## Локальный вариант

На компьютере, где запущен личный сервер, на стартовой странице есть явная ссылка на `http://127.0.0.1:8097/`. Это запасной локальный вариант и он не работает на чужих устройствах.

## Публикация

Пакет рассчитан на отдельный репозиторий и GitHub Pages: все ссылки на ресурсы относительные (`styles.css`, `config.js`, `app.js`), поэтому работают и по адресу вида `https://<account>.github.io/<repo>/`.

Положите содержимое этой папки в корень отдельного Git-репозитория. Workflow `.github/workflows/deploy-pages.yml` соберёт артефакт строго из пяти публичных файлов: `index.html`, `styles.css`, `app.js`, `config.js` и `.nojekyll`. В Settings → Pages выберите GitHub Actions как источник публикации.
